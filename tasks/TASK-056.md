# TASK-056: Fix iframe template EPUB 3 compliance

**Epic:** E2E testing
**GitHub Issue:** #621 — https://github.com/triplecanopy/b-ber/issues/621
**Scope:** templates, grammar-iframe, shapes-directives

## Description

The `b-ber-grammar-iframe` template generates HTML attributes that are not
valid in EPUB 3 XHTML, causing EPUBCheck errors when an iframe directive
appears in an epub build.

### EPUBCheck errors produced by the current template

| Error code | Attribute / cause |
| ---------- | ----------------- |
| RSC-005    | `scrolling` — not allowed in EPUB 3 XHTML |
| RSC-005    | `frameborder` — not allowed in EPUB 3 XHTML |
| RSC-005    | `webkitallowfullscreen` — proprietary, not allowed |
| RSC-005    | `mozallowfullscreen` — proprietary, not allowed |
| RSC-005    | `width="%"` — must be an integer |
| RSC-006    | Remote iframe `src` — not allowed in EPUB OCF |

### Current state (as of TASK-041)

`scrolling` and `frameborder` have been removed from `htmlIframeAttributes`
in `b-ber-shapes-directives` and from the `defaults` object in
`b-ber-grammar-iframe/src/helpers.ts` (TODO comments added pointing here).

The `webkitallowfullscreen` / `mozallowfullscreen` attributes are only
present in the installed bber v3.0.8-next.61 static template string — they
are not generated by the current monorepo source.

> **Correction (2026-11-24):** this section is out of date. The current
> source still generates all six errors in the table above, through
> `b-ber-templates`' figure-page template. See Findings.

The `width: '100%'` default and remote-src issue still need to be resolved.

## Findings

### 2026-11-24: the errors come from the figure-page template

Found while timing builds for TASK-160. On `main` at `72066c35`, `bber build
epub` on the kitchen-sink fixture exits 1, and EPUBCheck reports six errors on
`OPS/text/figure-ch-02-iframe-01.xhtml`, line 30. They are exactly the six in
the table above:

- RSC-005: `width` must be an integer;
- RSC-005: `webkitallowfullscreen`, `mozallowfullscreen`, `frameborder` and
  `scrolling` not allowed;
- RSC-006: remote resource reference.

**Where they come from.** All six are produced by the `iframe` template in
`b-ber-templates/src/figures/helpers.ts:178–196`, which writes the epub figure
page. It hardcodes the four disallowed attributes, and it writes `width` from
the directive's data. That width defaults to `'100%'` in
`b-ber-grammar-iframe/src/helpers.ts:55`.

**Why TASK-041's change didn't fix them.** TASK-041 removed `scrolling` and
`frameborder` from the *inline* path: `createIframeInline` and
`htmlIframeAttributes`. But an `iframe-inline` never renders in an epub. It
renders the unsupported message, because `grammar-iframe` supports inline
embeds only in reader and web (TASK-160 Findings, group 1). The path that does
render in epub, the figure page, was never changed.

**The Vimeo figure template** (`figures/helpers.ts:235`) emits the same
attributes. It doesn't affect EPUBCheck, because the `epub` and `mobi` figure
tables render Vimeo as unsupported. It matters only for web and reader, which
are not validated against EPUB.

**Option 3(a) is the consistent fix.** TASK-160's inventory found that epub
is inconsistent: the figure page renders a live iframe, but `iframe-inline`
renders the unsupported message. Rendering the unsupported placeholder on the
epub figure page, as epub already does for Vimeo, removes all six errors at
once. It also makes iframe behave the same as Vimeo, and inline the same as
figure. TASK-160's plan points here for that fix. It changes epub output, so
TASK-152's golden snapshot is regenerated in the same PR.
